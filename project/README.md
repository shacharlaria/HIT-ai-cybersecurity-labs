📌 Overview & Problem Statement
Modern enterprise Security Operations Centers (SOCs) face two critical operational bottlenecks:

Alert Fatigue: SOC analysts are overwhelmed by thousands of daily alerts generated by rigid static rules, many of which are benign noise or false positives.
Signature Blindness: Traditional signature-based detection mechanisms (such as Snort/Suricata rules) consistently fail against evasive variants, zero-day behaviors, and stealthy reconnaissance patterns.
The Hybrid SOC Threat Detector addresses these challenges by deploying a containerized, two-tiered detection architecture:

Deterministic Engine: Rapid pattern-matching layer capturing known attack signatures, brute-force attempts, and protocol anomalies with minimal latency.
Unsupervised Machine Learning (Isolation Forest): Analyzes multidimensional network feature distributions to isolate behavioral outliers without requiring pre-labeled training datasets.
Automated STIX 2.1 CTI Enrichment: Real-time resolution of detected anomalies against the MITRE ATT&CK STIX framework (enterprise-attack-mini.json), mapping raw indicators directly into standardized tactics, techniques, and triage evidence.

🔬 Feature Engineering & Behavioral Analysis
The detector continuously ingests streaming network telemetry generated by the simulator, aggregating connection records across sliding time windows per source IP. To detect evasive threat profiles, the system extracts a 5-dimensional behavioral feature vector:

Connection Velocity & Frequency: Tracks the rate of connection attempts per second. Abrupt spikes indicate automated scanning loops, brute-force attempts, or volumetric traffic.
Target Port Diversity (Port Entropy): Measures destination port distribution. High entropy signals horizontal or vertical reconnaissance sweeps across sensitive service ports (SSH 22, HTTP 80, HTTPS 443, MySQL 3306).
Inter-Arrival Time (IAT) Variance (Jitter): Evaluates the timing regularity between sequential packets. Near-zero variance identifies script-driven automated execution versus natural human timing patterns.
Failed Connection / Handshake Ratio: Tracks unestablished TCP handshakes (SYN without ACK) and connection resets (RST), flagging unreachable host sweeps and unauthorized probing.
Payload & Request Length Distribution: Differentiates between benign high-volume data transfers and low-byte exploratory probes or malformed payloads.
🧠 Anomaly Detection Core: Isolation Forest
Unlike standard supervised classifiers that require massive, perfectly labeled datasets of malicious activity, the behavioral tier utilizes an Unsupervised Isolation Forest algorithm:

Anomaly Isolation Logic: Malicious reconnaissance patterns are "few and different" from baseline operational traffic. As statistical outliers in feature space, they require substantially fewer recursive random partitions to isolate.
Isolation Trees (iTrees): The ensemble builds randomized decision trees. Normal corporate traffic clusters densely and requires deeper tree paths, whereas anomalous vectors are isolated close to the root with short path lengths.
Dynamic Anomaly Scoring: Each monitored IP receives a normalized anomaly score. IPs breaching the statistical decision boundary are immediately flagged and dispatched for automated CTI enrichment.

🐳 Containerized Microservices
The entire environment is orchestrated via Docker Compose, dividing operations into three stateless microservices:

Service	Container Name	Port Mapping	Core Responsibility

🚀 Quick Start & Deployment
Prerequisites
Docker (v20.10+) and Docker Compose installed on your host machine.
1. Clone the Repository
git clone https://github.com/shacharlaria/HIT-ai-cybersecurity-labs.git
cd HIT-ai-cybersecurity-labs/project
2. Build and Launch Containers
docker-compose up --build
3. Access the SOC Console
Once initialization completes, open your browser at: http://localhost:8000

To stop all running services: docker-compose down
